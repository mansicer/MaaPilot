# maapilot-goals：目标

目标清单是 `private/goals.md`，完成或放弃的挪进 `private/goals-done.md`。写进去就是用户同意过的：之后每天日常推进它，要花的不再问。

## 格式

```markdown
## 遥 精2
- 状态：进行中
- 对象：干员 遥 → 精2 1级
- 原话：把遥练到精2（2026-09-30）
- 同意：2026-09-30 21:40，已报：龙门币约 59 万、经验约 36 万、聚合剂 2、提纯源岩 9…
- 花合成玉/源石：否

分解与进展（agent 自由写）：
- 缺辅助芯片，靠 PR-C 刷；合成要换加工站干员
- 10-01：合成做了一半，差聚合剂 2
```

- 5 行固定字段只用 `bin/maapilot goals add / update / remove` 改；"分解与进展"是你的工作笔记，`goals update --note` 追加一行，或直接编辑。第二天的你要靠它接着做：写清拆成了哪几步、卡在哪、下一步是什么。
- 缺多少、要几天这类会变的数不写成事实，每次用 `calc` 现算。
- **对象**一行的写法（`calc need` 直接能用）：

| 写法 | 例 |
|---|---|
| `干员 <名> → 精<E> <L>级` | `干员 遥 → 精2 1级` |
| `干员 <名> → <L>级` | `干员 香草 → 40级` |
| `干员 <名> → 技能 <N>级` | `干员 遥 → 技能 7级` |
| `干员 <名> → 技能<K> 专<M>` | `干员 能天使 → 技能3 专3` |
| `干员 <名> → 模组<类型> <N>级` | `干员 泥岩 → 模组X 3级` |
| 同一干员几项用 `，` 连 | `干员 遥 → 精2 60级，技能 7级，技能3 专3` |
| `材料 <名> × <N>` | `材料 聚酸酯组 × 10` |
| `关卡 <编号>`（三星通关） | `关卡 12-17` |
| `其他 <文字>` | `其他 泥岩模组X的模组任务` |

- **标题**短而唯一：`遥 精2`、`能天使 技能3专3`、`聚酸酯组×10`、`12-17 三星`。
- **花合成玉/源石**：这个目标本身要花合成玉或源石时写"是"（很少见，例如用户要的东西只能用源石买）。写"是"也不等于放行：每次花之前照样单独问、`guard allow`。

## 用户说要练谁 / 做什么

1. **听懂、写成对象**。干员名不确定就 `bin/maapilot data operator <名>`（认不出会给相近的名字，跟用户确认）。
   看一眼上限：`data operator` 给稀有度和各阶段等级上限（三星最多精1、一二星不能精英化、技能 5 级以上要精1、专精要精2 且技能 7 级、模组要精2 到一定等级）。做不到的直接告诉用户。
2. **现在的练度**：`bin/maapilot state show box --op <名>`（精英化、等级；快照太旧或没有就 `state box`，要几分钟）。
   技能等级快照里没有：`bin/maapilot state op <名>`（进干员页读精英化、等级、技能等级，约一分钟，只读）。
   专精、模组读不了：先看这个目标的笔记或记忆；没有就问用户"现在专几？不清楚的话我去游戏里看一眼"（看法见 `maapilot-training`）。
3. **算账**：`bin/maapilot calc need "<对象>" --from "<当前>"` → `need`（总共要多少）、`have`、`short`（缺多少）、`craftable`（缺的里面能合成的）。
   前提练度（专精要精2、技能 5 级以上要精1、模组要精2 到一定等级）没写进对象也会算上，`assumed` 里写着"已算上练到…"：报数时一起说。
   `assumed` 里有"按…算"的猜测（技能几级、专几），能查的先查（`state op`），查不了就在报数时说清是按什么算的。
   缺的基础材料再 `bin/maapilot calc stages <物品>=<数量> …` → 刷哪几关、共多少理智、约几天。
4. **能马上做完吗？**
   - `short` 为空（或缺的全能用仓库材料合出来），而且一次能做完（升级、精英化、升技能、开一阶专精、合成）：这是**即时任务**。
     一句话说清花什么（"要花约 18 万龙门币、4 万经验和几样材料，仓库都够，我这就做"），然后直接做（`maapilot-training` / `maapilot-base`），不写目标。
     会用掉**其他进行中目标**要的材料时，先告诉用户、问先给谁。
   - 否则（要刷材料、要好几天、专精要好几阶）：写成**目标**，走第 5 步。
5. **报数、等同意**。用玩家的话一次说清：
   - 总共要花：龙门币（约数）、经验、主要材料；
   - 仓库够的、缺的；缺的里面能合成的、要刷的；
   - 刷图大约要多少理智、按每天的理智约几天；
   - 会不会花合成玉 / 源石（一般不会）。

   例："遥到精2 1级一共要龙门币约 59 万、经验约 36 万，还有辅助双芯片 1、聚合剂 2、提纯源岩 9 等。仓库缺辅助双芯片（要刷 PR-C 芯片本，约 3 天）和 2 个聚合剂（能合成）。之后每天日常会自动推进，不花合成玉和源石。要加成目标吗？"
6. **用户同意后写入**：

   ```
   bin/maapilot goals add --title "遥 精2" --object "干员 遥 → 精2 1级" --said "把遥练到精2（2026-09-30）" --approved "2026-09-30 21:40，已报：龙门币约 59 万、经验约 36 万、辅助双芯片 1、聚合剂 2…" --note "缺辅助芯片，靠 PR-C 刷；聚合剂能合"
   ```

   `--said` 写用户原话加日期；`--approved` 写同意的时间和报过的数。写完能马上做的部分就现在做（例如先升到精1满级、先合聚合剂），告诉用户剩下的交给每天的日常。
   用户改了主意（要练到更高、换个技能）：重新算、重新报，同意后 `goals update --object … --approved …`。

## 关卡、模组任务这类

`calc need` 对 `关卡`、`其他` 算不了，由你分解：
- **关卡**：先看用户的干员能不能打（`maapilot-battle`：找作业、看作业要哪些干员和练度）。缺练度就把缺的写进分解："要 XX 精2 60级 → 缺材料 …"，报数时把这些养成的花费一起报。
- **模组任务**：`data operator <干员>` 的 `modules[]` 有每个模组的任务原文（`missions`）和解锁条件（`unlock`）；打法见 `maapilot-battle`，加上解锁 / 升级模组的材料（同一处的 `levels`）。
- 分解出来的每一步写进"分解与进展"，做完一步勾一步。

## 进度、暂停、放弃、完成

- 用户问进度：`goals list`，每个目标 `calc need` 现算还差什么，按笔记说到了哪一步、大概还要几天。
- 暂停："先别练了但留着"：`goals update <标题> --status 暂停`；恢复改回 `进行中`。
- 放弃："不要了"：`goals remove <标题> --status 放弃 --reason "用户说…（日期）"`。
- 完成：在屏幕上或用 `calc need`（`short`、`need` 都为空）核对确实达到了，`goals remove <标题> --status 完成 --reason "<核对依据>"`，告诉用户。

## 问用户的情形

- 写目标前：报完数，等用户明确同意；
- 即时任务会用掉别的目标要的材料时；
- 当前技能 / 专精 / 模组等级不知道时；
- 目标卡住很久（打不过、材料刷不出来）时，问要不要换做法或放一放。

## 记住什么（写进自动记忆）

- 用户的养成偏好（"先练主力，不急的别占材料""专精默认专三"），写明是用户哪天说的。
- 用户对"多大的花费不用问我"之类的回答。
- 不记目标本身和进度——它们在 `goals.md` 里。
