# maapilot-recovery：出错了怎么办

先弄清卡在哪，再动手。每点一下都截图看结果。

## 1. 先看

1. **先看失败那一刻的截图**：`maa` 任务失败时程序当场截了一张，还找了 MAA 自己在这段时间存的截图，都在 `data.evidence`
   （日常交给你时在 `data.handoff.evidence`）：`shot_now` 是失败那一刻，`maa_shots` 是 MAA 出错时存的（按时间），`missing` 是没取到的。用读图逐张看。
   提示框常常一闪而过，等你截图时已经没了，所以这几张比现在的屏幕更能说明出了什么事。
2. **再查经过**：`maapilot maa why`（默认最近一次失败的 maa 任务；指定哪项用 `--task <项>`，指定时间段用 `--since <时间> --until <时间>`）。
   它只读 MAA 的详细日志，不碰模拟器，只给事实、不给结论：`steps`（MAA 一步步做了什么、认出 / 点了什么）、`tried`（它在找哪一页）、`errors`（找不到的页面）、
   `last_match`（最后一次认出东西）、`ocr`（这段时间看到过的所有字，带时间）、`waits`（等加载、等服务器的时长）、`screencap_failures`、`connection`、`error_lines`、
   `screenshots`（MAA 存的截图）。**原因由你判断**，可以这样读：
   - 先看截图（`shot_now`、`maa_shots`、`screenshots`），截图比日志可靠；日志和截图对不上时以截图为准。
   - `ocr` 里出现标题页的字（"开始唤醒"、"扫码登录"、"账号管理"、"玩家 187****…" 这种打码的账号）→ 游戏被登出了。看它第一次出现的时间。
   - 登出之前有一长段"正在提交"之类的等待（`waits` 十几秒以上）→ 多半是网络或服务器断了；看到"其他设备登录"之类的字 → 账号在别处登录了。
   - `last_match` 之后再没认出任何东西、`errors` 里全是找不到某一页 → 那之后屏幕变成了 MAA 不认得的样子（弹窗、标题页、别的页面），看那段时间的截图。
   - 一开始就没认出任何东西（`last_match` 为空）→ 任务开始时游戏就不在 MAA 认得的页面。
   - `screencap_failures` 多 → 模拟器连接有问题。
   - 看不出就说看不出，别编原因；拿不准是不是别的设备登录，就问用户。
3. 现在停在哪：`maapilot screen shot`，用读图看截图。要找字就 `maapilot screen ocr`（`--find "<正则>"` 只要匹配的）。
4. 失败的命令给了什么：`error.code`、`error.hint`、`data.log`（maa-cli 的日志，用读文件工具看最后一段；不用 `cat`/`grep` 接管道，这种命令要用户批准，用户不在时就卡住了）、`data.errors`。

## 2. 常见情形

| 看到 | 做法 |
|---|---|
| 登录公告（"活动公告""系统公告""资讯速报"） | 点右上关闭（约 1203,70） |
| 月签到日历 | 右上关闭（约 1215,68） |
| 签到活动页（一排"DAY"卡片，左下"结束时间"） | 能领的点一下领、弹"获得物资"点掉；右上 ✕（约 1232,100）关掉 |
| 多选一奖励（"选一样"） | 不花资源，但选择是用户的：记忆里用户说过"你替我选"才选；否则关掉，告诉用户 |
| "当前系统发生未知故障，尝试重新恢复"（掉线） | 点 ✓（约 640,491），等十几秒自己重连；回到了标题页（"开始唤醒"）就是被登出了，按「掉线、被登出」（会话里先问用户再登录）；还不行 `maapilot maa closedown` 再 `maapilot maa startup` |
| 服务器维护 | 什么都别点，告诉用户维护中，下次日常照常；不用接管 |
| "是否确认离开罗德岛基建？" | 确认（约 842,495） |
| 设置页（被误点开） | 左上返回（约 85,45） |
| "角色档案"教程 | 左上关闭（约 156,109） |
| 黑屏、转圈、加载中 | 等 2–5 秒再截；一直这样就 `maa startup` |
| 正在下载资源 / 更新 | 等它下完；要重启游戏的按提示确认 |
| 战斗中、剧情 | 剧情点右上"跳过"并确认；战斗中的交给 MAA 或等它结束 |
| 有**花钱**的页面（采购中心、寻访、"是否消耗源石 / 理智液恢复理智"、礼包、标价 ¥） | **不要点确认**，`input back` 离开。这些只在用户同意后才做 |

**回首页**：首页的标志是右上有"终端"。
- 左上菜单（约 270,38）→ 菜单里的"首页"（约 92,260）；
- 没有菜单的全屏页：`maapilot input back`，一次一下，每次截图；
- 还是回不去：`maapilot maa startup`（启动或登录后会自己回首页，`data.home` 为 `true` 就是回到了）；最后手段 `maapilot maa closedown` 再 `maapilot maa startup`。

## 3. 按错误码

| 情形 | 做法 |
|---|---|
| `maa` 任务 `offline`，或截图 / `maa why` 的字显示停在标题页（"开始唤醒"） | 维护就等，别反复重试；其余按下面「掉线、被登出」 |
| `maa` 任务 `maa_failed` | 看日志最后几行和屏幕，常是弹窗挡住：清掉、回首页，再跑一次这个任务。同样的错两次就停，写清卡在哪 |
| 剿灭 `maa_failed`，屏幕上关卡页没有"代理指挥"或提示不能代理 | 这张剿灭图还没 400 杀满过，不能代理：别重试，写进总结（要用户决定：找作业打一次、或这周先不打）。程序不会自动整周跳过，每次日常都会交回给你 |
| `maa fight` `not_open` | 关卡今天不开：换关，不是故障 |
| `op` / `craft` `shortcut_failed` | 看 `data.stage` 和截图，按 `maapilot-training` / `maapilot-base` 手动接着做 |
| 退出码 4（被占用） | `maapilot lock status` 看谁占着、做到哪；想知道它在干什么可以 `maapilot screen shot` 看一眼（截图不用锁）。在跑日常就等它；持有进程已经不在了（残留）才 `maapilot lock release` |
| 退出码 5（环境） | `maapilot doctor`，按每项的修复建议；要用户动手的（开模拟器、装软件）告诉用户 |
| `upstream_format`，或启动检查 / 汇报里有"外部数据：…的数据格式变了" | 森空岛、MAA、官方公告、企鹅物流这些外面的数据改了格式，程序得开发者来改。用玩家的话告诉用户哪部分受影响、现在怎么凑合（例如"森空岛那边改了格式，理智先从首页认，干员练度改用游戏里识别，慢一点"），不要自己想办法绕过去，也不用反复重试 |
| 模拟器卡死、截图失败 | 请用户重启模拟器；`doctor` 确认连上再继续 |

## 4. 掉线、被登出

截图或 `maa why` 看到的字显示游戏回到了标题页（"开始唤醒"）、出现掉线 / 网络 / 别的设备登录的提示，或任务带着 `offline` 失败时：

- **服务器维护**：什么都别点，告诉用户维护中；不重登、不重试。
- **用户在会话里叫你做的事**（包括用户说的"跑一次日常"）：重新登录会把在别的设备上玩的用户挤下线，所以先问一句，同时开始计时：
  1. 跟用户说（先说发生了什么）："基建做到一半游戏被登出了，回到了开始唤醒的页面。是不是在别的设备上登着这个账号？5 分钟内没回复，我就重新登录接着跑。"
  2. 起一个 5 分钟的计时器 `sleep 300`：harness 能在后台命令结束时叫醒你的就放后台跑；叫不醒的前台跑，用户这期间说的话会在它结束后看到。
  3. 用户先回答：照用户说的办。在别的设备上玩着 → 不登录、不重跑，告诉用户玩完说一声"接着跑日常"，你再 `maapilot maa startup` 后用 `maapilot daily run --only <没跑完的几项>` 补上（这次日常先别收尾，等他说；当天没等到就收尾，没跑的写进总结）；
     不是 / 可以登 → 马上重新登录接着跑（下一步）。
  4. 计时器先到（用户没回复）：重新登录 —— `maapilot maa startup`（`data.home` 为 `true` 就是回到了首页；也可以截图看到"开始唤醒"就点它），
     再把没做完的接着跑（日常交给你的就 `maapilot daily run --only <rest>`）。跟用户说一句"5 分钟没等到回复，已经重新登录接着跑了"。
  5. 计时器没用了（用户已经回答）就不用管它，它到点结束不影响什么。
- **定时叫醒你的日常**（这次日常是你按定时的提示用 `--trigger schedule` 开的）：用户多半不在，不问、不等：直接 `maapilot maa startup` 重新登录，
  `maapilot daily run --only <rest>` 接着跑，总结里写明"几点被登出、已重新登录"。
- 重新登录后又很快被登出：不要再登，说明有人在别处玩着或网络不稳，写清楚，等用户。

不用别的方式通知用户（不发消息、不弹窗），就在对话里问。

## 5. 货币对账停机

`guard check` / `guard snapshot` 或 `daily run` 退出码 3（`currency_decreased`），或会话开头 `next: "guard"`：合成玉或源石少了，而没有记下的同意。日常会一直停着。
（对账只在"上次对账之后动过会花钱的操作"时才会拿旧的起点比，所以用户两次日常之间自己在游戏里花的一般不会被算进来。）
1. `maapilot guard status` 看少了多少、什么时候。
2. 告诉用户："合成玉少了 600（9 月 30 日 21:40 之后），我没有记录到你同意过这笔花费，所以日常先停下了。是你自己在游戏里花的吗？"
3. 用户说是自己花的 / 同意这笔：`maapilot guard allow 合成玉 600 --reason "用户说是自己寻访用的（日期）"`（宿主可能还要用户点一次同意），再 `maapilot guard check`，对上了就恢复。
   有日常在跑或还没收尾时这条命令会被拒：先把那次日常 `daily done` 收尾，再记。
4. 用户也不知道：别放行，请用户在游戏里查（寻访记录、采购中心），可以帮着截图看。

## 6. 日常里交回你（`handoff`）

`daily run` 停在失败的那一项交给你：`data.handoff` 里是哪一项、为什么、`rest`（它和后面还没跑的）、`evidence`（截图）。
1. 按「先看」看截图、`maapilot maa why`，判断原因，再看屏幕、按上面处理（被登出按「掉线、被登出」）。
2. **把游戏留在首页**，再 `maapilot daily run --only <rest 用逗号连起来>` 接着跑：还是这一次日常，记在同一份汇报里。
   同一项处理过还失败、或处理不了：不再试，`--only` 里去掉它、后面的照跑，在总结里写清卡在哪、要用户做什么。
3. 要用户决定的、会花钱的：用户叫你跑的日常就当场问；定时叫醒你的日常不问、不做，写进总结"要你决定的事"（`guard allow` 这时也会被拒）。
4. 整次日常最后照 `maapilot-daily` 收尾（`daily done`），总结里写上：卡在哪、怎么处理的、补跑成没成。

## 7. 会话里

处理完告诉用户：什么坏了、怎么处理的、现在好了没有。用户自己让你做的事（不在日常里）失败了，处理完接着做；日常里失败的项照上一节接着跑。
处理不了：说清卡在哪、屏幕上是什么，请用户自己看一眼。

## 问用户的情形

- 页面上有花钱的按钮、要不要点；
- 多选一奖励选哪个（记忆里没有"你替我选"时）；
- 合成玉、源石少了是不是用户自己花的；
- 要用户重启模拟器、手动登录时；
- 游戏被登出时，是不是在别的设备上登着（用户叫你做的事里问，5 分钟不回就重新登录；定时日常不问，见「掉线、被登出」）。

## 记住什么（写进用户偏好 private/memory/）

- 新遇到的卡住页面：长什么样（关键字）、怎么出去的、有没有用。下次同一页直接照做。写明日期。
- 用户关于代选、掉线后要不要重试之类的回答，写明是用户哪天说的。
- 不记当次的运行编号、截图路径。
