# maapilot-feedback：把反馈发给开发者

用户全程只在对话里说话：命令都由你跑，要上传的内容由你在对话里给用户看，用户说"可以"才发。
没有用户在对话里亲口同意，什么都不上传；定时日常里不发反馈（程序也会拒绝）。

你**主动提**的时机：同一件事反复做不成、你判断是 MaaPilot 自己的问题（不是用户环境的问题）时，可以问一句"要不要把这个问题反馈给开发者"。用户说不用就不再提。

## 第一步：问清楚、写会话经过

1. 用户的原话不够清楚时问一句（一次只问一个问题）：想反馈的是哪件事、期望的是什么。
2. 把这次会话里和这件事有关的经过写成一个文本文件（放在 `private/feedback/` 下，名字随意，如 `private/feedback/session.md`）：
   - 按时间顺序：用户说了什么（相关的原话）、你跑了哪些命令、每条的结果（成败、错误代码、关键的输出）、你当时怎么判断的、最后卡在哪。
   - 对话被压缩过、早先的细节你已经看不到时，如实写"前面的经过已经看不到了"，不要编。
   - **写的时候就脱敏**（见下面「脱敏」）。
3. 你所在的 harness（名字、命令行还是桌面版、知道版本就带上）和你的模型（具体型号）。不确定就写"不确定"，**不要猜**。

## 第二步：问要不要带更多（默认都不带）

逐项问，用户说要才带。每项说清是什么、里面可能有什么：

| 内容 | 怎么带 | 跟用户说什么 |
|---|---|---|
| 原始会话记录（带每次工具调用的参数和输出） | 你自己整理成一个文本文件，`--raw-session-file` | 比上面的经过详细得多，开发者排查更快；内容长，你会先去掉个人信息，用户想看哪段可以让你贴出来 |
| 截图 | `--shot <private/ 下的 PNG>`（最多 4 张） | 画面上可能有游戏昵称和 UID，程序改不了图片 |
| MAA 日志末尾 | `--maa-log` | 最近一次 MAA 任务的日志最后 200 行 |
| 联系方式 | `--contact` | 想收到回复才留 |

问题本身一两句话就能说清（纯建议、文案问题）时，不用问这些。

原始会话记录怎么整理：你的 harness 把会话存成了文件、你也找得到时，可以从那里取这次会话的内容；否则按你还看得到的上下文写。
每次工具调用写清：调了什么、参数、输出（很长的输出留开头和结尾）。不带你的系统提示和思考过程。
读过的 `private/` 下的文件内容（偏好、目标、配置）不带原文，写一句"读了某某文件"。

## 第三步：起草

```
maapilot feedback draft --text "<用户的反馈原话>" --session-file <会话经过的文件> --harness "<harness>" --model "<模型>" --category <bug|experience|idea|other>
```

知道才加：`--harness-version`、`--effort`。用户同意了才加：`--raw-session-file`、`--shot`、`--maa-log`、`--contact`。
对话里出现过、程序认不出的个人信息（用户的真名、别的账号、公司名……）用 `--mask "<字样>"` 指定，可以写几次。

程序会自己收集（不用你做）：MaaPilot 和 MAA 的版本、操作系统、环境检查各项通不通过、最近 40 条命令的成败和错误代码、最近一次日常各项成败。
命令的参数和结果、目标、偏好、货币数量都不在里面。程序还会把路径、用户名、模拟器地址、森空岛的 UID 和昵称再换一遍（`scrubbed` 是每一类换了几处）。

结果里的 `id` 是草稿编号，`digest` 是这一版内容的指纹，`includes` 是里面有什么。这一步什么都没上传。

## 第四步：在对话里给用户看，问能不能发

照 `feedback show <编号>`（要全文加 `--part info|session|raw-session|maa-log`）的内容说，不要凭记忆说：

- **贴全文**：用户的反馈原话、你写的会话经过（`--part session` 取脱敏后的那一版来贴）。
- **各说一句**：你用的 harness 和模型；版本和系统；"环境检查 N 项的结果、最近 N 条命令的成败、最近一次日常的结果"。用户想看就贴。
- **带了才说**：原始会话记录（多少字、你和程序去掉了什么）、截图（哪几张、画面上是什么）、MAA 日志、联系方式。
- 说明发到哪里（MaaPilot 开发者的服务器）、保留 90 天。

然后问一句：可以发吗？用户的回答只有三种：

- **可以** → 第五步。
- **改一改**（去掉某部分、某句话不要、某个词要隐去）→ `maapilot feedback redact <编号>`：`--remove raw-session|maa-log|shots|contact`、
  `--mask "<字样>"`、`--text "<新的原话>"`、`--session-file <改过的文件>`、`--raw-session-file <改过的文件>`。
  改完 `digest` 变了：把改过的部分重新给用户看，再问一次。
- **不发了** → `maapilot feedback discard <编号>`。

## 第五步：发送

```
maapilot feedback send <编号> --digest <给用户看过的那一版的 digest>
```

- 成功：告诉用户反馈编号（`server_id`），以后想问进展可以报这个编号。
- `draft_changed`（退出码 2）：草稿和给用户看过的不一样了。`feedback show` 看现在的内容，重新给用户看、同意后带新的 `digest` 再发。
- `network` / `upload_failed` / `rate_limited`（退出码 1）：没发出去，草稿还在。告诉用户，稍后原样再发一次（内容没变就不用再问）；一直不行，告诉用户可以去 GitHub 提 issue。
- `too_big`（退出码 2）：包超过 5 MB。问用户去掉截图还是原始会话记录，`redact` 后重新给用户看。
- `needs_user`（退出码 3）：有日常在跑或没收尾。等 `daily done` 收尾后再发。

## 脱敏

三层：你写的时候处理，程序再兜底换一遍，最后用户看过才发。你这一层要做的：

**一律去掉**（换成 `<昵称>`、`<UID>` 这样看得出是哪一类的记号）：
- 游戏昵称、UID、森空岛的任何凭据；手机号、邮箱、真名。
- 模拟器地址、电脑上的路径（写成 `<项目>/private/…`）、电脑的用户名。
- 对话里出现的和 MaaPilot 无关的内容（别的项目、别的账号、私事）。
- 用户偏好（`private/memory/`）和目标（`private/goals.md`）的原文。

**和问题有关才留**：干员名和练度、材料数量、关卡。无关的不写。

**留着**：命令、错误代码、报错原话、界面上的字、时间。这些是排查用的。

拿不准某样东西算不算个人信息：去掉，并在给用户看的时候说一声"某处我隐去了"。
